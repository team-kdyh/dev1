# 세미콘 스킬 기반 설계

## 범위

이번 단계는 세미콘 스킬을 점진적으로 구현하기 위한 최소 기반과 워치 메딕의 기본 회복만 다룬다. 오차드, JSON 스킬 해석기, 시대 해금, 나머지 고유 스킬은 포함하지 않는다.

## 구조

- 시뮬레이션 유닛은 스킬용 정수 타이머와 활성 상태 목록을 보유한다.
- `StatusEffect`는 종류, 남은 틱, 수치, 부여자 ID를 저장한다. 모든 시간은 정수 틱이다.
- 공통 효과 함수가 회복과 상태 적용을 담당한다. 유닛 규칙은 대상 선택과 발동 시점만 결정한다.
- 첫 유닛 규칙은 워치 메딕이다. 살아 있는 메딕은 30틱마다 반경 100 안의 부상당한 같은 진영 유닛을 체력 비율, 거리, spawnId 순으로 정렬하여 최대 3기에게 HP 6을 회복한다.
- 메딕 자신도 부상했다면 대상 후보가 될 수 있다. 죽은 유닛과 이미 최대 체력인 유닛은 제외한다.
- 회복은 최대 체력을 넘지 않으며 실제 회복량이 0이면 이벤트를 만들지 않는다.

## 틱 순서

기존 생산과 쿨다운 갱신 다음, 타겟팅 전에 `UpdateStatuses()`와 `RunSkills()`를 실행한다. 회복은 해당 틱의 공격보다 먼저 적용된다. 이 순서는 결정론 계약의 일부로 테스트한다.

## 스냅샷과 이벤트

- `UnitView.Buffs`는 현재 상태 종류의 깊은 복사본이다.
- `UnitView.SkillCooldownTicks`는 디버그와 향후 UI 연결을 위한 스킬 타이머 값이다.
- 회복은 `SimEvent`의 `Type = "heal"`, `Unit = 시전자`, `Target = 대상`, `Damage = 실제 회복량`으로 기록한다. 기존 계약 변경을 최소화하기 위해 이번 단계에서는 별도 Amount 필드를 만들지 않는다.
- 미래 결과에 영향을 주는 상태와 스킬 타이머는 체크섬에 포함한다.

## 결정론과 테스트

- 같은 입력은 매 틱 같은 회복 대상, 이벤트 순서, 체크섬을 만든다.
- 체력 비율 비교는 부동소수점을 쓰지 않고 교차곱으로 비교한다.
- 테스트는 회복 주기, 범위, 최대 3기, 최대 체력 제한, 결정론, 스냅샷 격리, 체크섬 포함을 검증한다.

## 이후 확장

A폰 집결 버프를 추가할 때 `StatusEffect`와 공통 능력치 계산을 확장한다. 실제로 두 번째 스킬에서 반복되는 발동·대상 선택 패턴이 확인된 뒤에만 일반화한다. 완성형에서는 JSON 스킬 데이터가 동일한 공통 효과 함수를 호출하도록 전환한다.
