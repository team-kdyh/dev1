이 브랜치(`feat/track-a-client`)를 이어받는 사람을 위한 문서입니다.
**이것만 읽어도 손댈 수 있게** 쓰는 것이 목적입니다.

읽는 순서: 이 문서 → [README.md](../README.md)(실행·경계) → [DEVLOG.md](DEVLOG.md)(왜 이렇게 생겼나).
C와의 미결 사항은 [contract-response-a.md](contract-response-a.md)에 있습니다.

## 1. 30분 안에 돌려보기

```bash
git clone https://github.com/team-kdyh/dev1.git
cd dev1
git checkout feat/track-a-client
npm install
npm run dev          # http://localhost:5173
```

필요한 것은 **Node 20+ 와 Git뿐**입니다. 시뮬(B)도 에셋(D)도 없어도 돌아갑니다.
`FakeSimAdapter`가 가짜 스냅샷을 30tick으로 뱉고, 유닛은 진영 색 + 티어 숫자 블록으로 나옵니다.

### 제대로 돌아가는지 확인하는 체크리스트

1. 스플래시 → 메인메뉴가 뜬다
2. **빠른 대전** → 지면·본진 2개·유닛이 보인다
3. `1`~`3` 키 또는 하단 버튼 → 유닛이 생산되고 왼쪽에서 걸어 나온다
4. 돈이 모자랄 때 버튼이 흑백 + 비용이 빨강, 누르면 버튼이 흔들리고 토스트가 뜬다
5. 적 AI가 2.5초마다 스폰 → 중앙에서 교전, 흰 플래시 + 데미지 숫자 + 처치 시 파티클
6. 드래그로 카메라 이동, `Space`로 자동 추적 복귀
7. 우하단 미니맵의 흰 프레임이 카메라를 따라 움직이고, 클릭하면 점프
8. 본진이 깨지면 슬로우모션 → 결과 화면
9. **메인메뉴 → 도감** → 18종이 진영·티어 필터와 함께 나온다

`npm run build`가 통과하면 타입도 깨끗한 상태입니다.

## 4. 절대 깨면 안 되는 규칙

이걸 어기면 조용히 망가지고 원인을 찾기 어렵습니다.

1. **스냅샷을 수정하지 않는다.** `unit.x = ...` 같은 코드가 생기면 잘못된 겁니다.
   프론트가 소유하는 건 뷰의 수명과 Y 좌표뿐입니다.
2. **`/sim` 내부를 import하지 않는다.** `contracts.ts`에서 **타입만** 가져옵니다.
3. **낙관적 상태 변경 금지.** 버튼을 눌렀다고 캐시를 깎지 않습니다. 거부는 시뮬이 합니다.
4. **전투 결과를 추측하지 않는다.** `EffectDirector`에 게임 판정이 들어가면 안 됩니다.
5. **숫자와 문구를 코드에 적지 않는다.** 전부 `BalanceData`에서 읽습니다.
   데이터가 없으면 **지어내지 말고 "데이터 없음"이라고 표시**합니다. 그게 현재 방침입니다.

## 5. 미구현 — 정직한 목록

- **§4.1 미해금 버튼의 조건 툴팁.** 자물쇠만 그리고 툴팁이 없습니다. 어느 시대에
  풀리는지가 현재 `BalanceData`에서 도출되지 않아서입니다. C의 `ages.json`에
  `tiers[]`가 있으므로 데이터가 합의되면 바로 가능합니다.
- **투사체와 `skill` 연출이 한 번도 화면에 나온 적이 없습니다.** 렌더러는 완성돼
  있지만 `FakeSimAdapter`가 `projectiles: []`를 보내고 `skill` 이벤트를 만들지
  않습니다. 역할 명세 §1.1이 FakeSim에 요구하지 않는 항목이라 임의로 넣지
  않았습니다. **B의 시뮬이 붙는 순간이 이 코드의 첫 검증입니다. 여기서 버그가
  나올 가능성이 가장 높습니다.**
- **자동 테스트 0개.** 렌더 코드라 가치가 낮다고 보고 미뤘습니다. 다만
  `Interpolator`의 alpha 계산과 `UnitButton`의 상태 판정은 순수 로직이라
  테스트할 수 있고, 특히 버튼 판정은 시뮬의 거부 판정과 **순서까지** 같아야 하므로
  회귀 테스트 가치가 있습니다.
- **사운드 전무** (M2), **반응형·터치** (M2), **네트워크** (M3).

## 6. 함정 — 실제로 걸렸던 것들

### 6.1 rAF를 두 개 돌리지 말 것

어댑터가 자기 `requestAnimationFrame`을 돌리고 Pixi ticker도 rAF를 돕니다.
한때 어댑터의 rAF를 걷어내고 ticker가 `advance(dt)`를 부르게 고쳤다가,
§1 인터페이스 준수를 위해 되돌렸습니다.

지금은 `Interpolator`가 **tick 번호가 바뀌는 순간을 직접 관찰**하므로 두 rAF의
순서에 영향받지 않습니다. **`SimAdapter`에 `advance()`를 다시 추가하고 싶어지면
DEVLOG 3단계를 먼저 읽으세요.** 같은 길을 두 번 가게 됩니다.

### 6.2 유닛의 죽음은 한 가지 경로로만 판정

`kill` 이벤트와 "스냅샷에서 사라짐" 둘 다로 알 수 있는데, **둘 다 쓰면 사망 연출이
두 번 재생됩니다.** `GameRenderer`가 스냅샷 쪽만 씁니다.

### 6.3 `initTextures()`는 `Application.init()` 이후에만

플레이스홀더 텍스처를 `renderer.generateTexture()`로 만들기 때문입니다.
`BaseView`/`UnitButton` 생성보다도 먼저여야 합니다.

### 6.4 `Camera.attach()`가 따로 있는 이유

`GameRenderer`가 생성 시점에 카메라를 필요로 하고(컬링·패럴랙스),
카메라는 `GameRenderer`가 만든 컨테이너를 움직여야 합니다. 순환을 끊으려고
컨테이너를 나중에 붙입니다. 생성자로 되돌리려다 순환에 걸립니다.

### 6.5 `onEvents` 콜백은 시뮬 step 중에 동기로 불린다

콜백 안에서 바로 연출을 재생하면 렌더 중간에 끼어듭니다. `Game`이 버퍼에 쌓고
프레임 경계에서 한 번에 소비합니다.

### 6.6 100ms 중복 차단은 공유해야 한다

키보드와 유닛 버튼이 각자 차단 창을 가지면 "버튼 클릭 + 숫자키"가 100ms 안에
두 번 나갑니다. `CommandGate` 하나를 둘이 같이 씁니다.

### 6.7 Pixi 마스크를 피했다

쿨다운 원형 오버레이를 마스크로 자르려다, 버전에 따라 마스크 객체가 그대로
그려질 여지가 있어 **버튼 안에 들어가는 반지름**으로 바꿨습니다.

### 6.8 계약 상수는 수동 동기화 부채

`TICK_HZ` / `TICK_MS` / `LOGICAL_MAX`가 `src/adapter/SimAdapter.ts`에 A측 사본으로
복제돼 있습니다. §10이 "타입만 import"라고 못박아서입니다.
**B가 이 값을 바꾸면 여기도 같이 고쳐야 합니다.** 컴파일 에러로 안 잡힙니다.

### 6.9 개발 환경

- Windows + OneDrive 동기화 폴더 + 한글 경로에서 작업했습니다. 경로 문제는 없었지만
  OneDrive가 "클라우드 전용"으로 내려놓으면 파일이 비어 보일 수 있습니다.
- Windows PowerShell 5.1에서 `git commit -m "..."`에 큰따옴표가 들어가면 인자가
  깨집니다. 여러 줄 메시지는 `git commit -F <파일>`을 쓰세요.
- 저장소 루트에 `클라이언트`라는 0바이트 파일이 있습니다. 출처 불명이라
  커밋에서 제외했습니다(untracked). 필요 없으면 지워도 됩니다.

## 7. 대기 중인 의존성과 열린 결정

| 항목 | 상대 | 상태 |
| --- | --- | --- |
| `Simulation` 클래스 → `LocalSimAdapter` | B | 대기 |
| 스냅샷 필드 확정 (A 요구 목록은 contract-response-a.md §4) | B | 대기 |
| `C-DEC-08` `roles[]` — **승인 필요 상대가 A** | C | **A가 찬성으로 답함** |
| `cooldown`이 생산 시간인지 재클릭 금지 시간인지 | C | **A가 질문 올림** |
| 밸런스 JSON 채택 | C | 데이터는 나왔으나 **잠정 상태라 미채택** |
| 진영별 아틀라스 (2048×2048) | D | 대기 |

C의 데이터는 `feat/track-c-implementation`에 있습니다. C 본인이
"팀 합의 전에는 승인된 공용 계약이 아니다"라고 명시했으므로 A는 붙이지
않았습니다. **주간 4인 동기화에서 확정되면 붙입니다.**
